## Sobre o Projeto

Este repositório documenta a minha jornada diária para me tornar um Engenheiro de Software .NET Pronto para o Mercado. 

Em vez de um estudo passivo, adotei uma metodologia estruturada baseada em módulos, entregáveis práticos e Projetos Finais de cada etapa. Todo o processo é acompanhado por versionamento rigoroso, resolução de problemas no LeetCode e produção de conteúdo técnico para o YouTube.

---

## Metodologia & Hábitos Diários

Para garantir consistência e evolução técnica contínua, sigo uma rotina diária:

- Estudo Diário: Mínimo de 30 minutos de prática em C# e .NET.
- Algoritmos: Resolução contínua de exercícios no LeetCode para aperfeiçoar o raciocínio lógico.
- Versionamento: Commits diários seguindo as boas práticas do mercado.
- Learn in Public: Explicação dos conceitos aprendidos em vídeo no YouTube para consolidar o conhecimento.

## Roadmap de Módulos & Missões

O plano de aprendizagem está dividido em 6 módulos progressivos:

| Módulo | Foco Técnico | Projeto Final |
| :--- | :--- | :--- |
| **c1-fundamentos-csharp/** | Sintaxe, Tipos, Condicionais, Loops, Exceções | Calculadora CLI / Task Manager |
| **c2-programacao-orientada-a-objetos/** | OOP, Abstração, Herança, Interfaces, Polimorfismo | Sistema Bancário CLI |
| **c3-csharp-moderno-e-linq/** | Generics, Lambdas, LINQ, Async/Await, Records | Processador de Dados JSON |
| **c4-ef-core-e-banco/** | SQL, Entity Framework Core, Migrations, CRUD | Sistema de Gestão de Inventário |
| **c5-aspnet-core-api/** | REST APIs, Controllers, DTOs, DI, Swagger, JWT | API REST Financial |
| **c6-testes-e-qualidade/** | xUnit, Mocks (Moq), FluentAssertions, SOLID | Suíte de Testes da API |

## Padrão de Versionamento (Conventional Commits)

Para manter o histórico limpo e rastreável, utilizo o padrão Conventional Commits:

- feat: Nova funcionalidade ou exercício concluído
- fix: Correção de bugs em exercícios/projetos
- boss: Conclusão de um projeto final/desafio do módulo
